# India Observed coding-agent instructions

## Scope
Build incrementally. Do not build automated publication, live protest tracking, participant identification, authentication, or a full editorial CMS without an approved issue.

## Required workflow
1. Read `README.md`, `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, and the issue.
2. Propose an implementation plan before changing files.
3. List every file to be created or modified and explain why.
4. Keep TypeScript strict and avoid `any` unless justified.
5. Add or update tests.
6. Run formatting, lint, type-check, tests, and build.
7. Report security implications and rollback steps.

## Non-negotiable product rules
- No autonomous publication.
- No live or tactical protest locations.
- No ordinary participant lists or unnecessary personal data.
- Every public factual claim must resolve to stored evidence.
- Source copies and syndicated reports must be grouped by underlying source family.
- Consequential changes require a correction history.
- Missing evidence remains missing.
